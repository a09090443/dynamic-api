# 主要使用情境

本章節描述系統的主要使用情境（Use Cases），展示典型的使用者操作流程。

## UC-1：動態部署 Web Service

**目標**：開發人員在不重啟系統的情況下部署新的 WSDL Web Service

### 前置條件
- 開發人員已開發並打包 Web Service JAR 檔案
- JAR 檔案包含繼承 `WebserviceBase` 的實作類別
- 開發人員已登入系統

### 主要流程
1. 開發人員進入「Endpoint 管理」頁面
2. 點擊「上傳 JAR 檔案」按鈕
3. 選擇本地的 JAR 檔案並上傳
4. 系統驗證檔案格式與大小，顯示上傳成功訊息
5. 開發人員點擊「新增 Endpoint」按鈕
6. 填寫 Endpoint 資訊：
   - Publish URI：`/ws/company`
   - Bean Name：`companyWebService`
   - Class Path：`com.company.webservice.impl.CompanyWebServiceImpl`
   - 選擇已上傳的 JAR 檔案
7. 點擊「儲存」，系統建立 Endpoint 記錄（狀態：停用）
8. 開發人員點擊「啟用」按鈕
9. 系統動態載入 JAR，發布 Web Service
10. 顯示「啟用成功」訊息，狀態更新為「已啟用」

### 後置條件
- Endpoint 已啟用並可透過 WSDL 存取
- 外部系統可呼叫：`http://localhost:8080/ws/company?wsdl`
- JAR 檔案狀態更新為 `INUSED`

### 替代流程
- **4a. 檔案格式錯誤**：系統顯示「僅支援 .jar 格式」，返回步驟 3
- **4b. 檔案過大**：系統顯示「檔案大小超過 50MB」，返回步驟 3
- **9a. 類別載入失敗**：系統顯示「類別不存在於 JAR 中」，Endpoint 保持停用狀態
- **9b. CXF 發布失敗**：系統顯示「服務發布失敗」，回滾狀態變更

## UC-2：動態部署 RESTful API

**目標**：開發人員在不重啟系統的情況下部署新的 RESTful Controller

### 前置條件
- 開發人員已開發並打包 RESTful JAR 檔案
- JAR 檔案包含繼承 `RestfulBase` 的 Controller 類別
- 開發人員已登入系統

### 主要流程
1. 開發人員進入「Restful 管理」頁面
2. 點擊「上傳 JAR 檔案」按鈕（若尚未上傳）
3. 選擇本地的 JAR 檔案並上傳
4. 系統驗證檔案格式與大小，顯示上傳成功訊息
5. 開發人員點擊「新增 Restful」按鈕
6. 填寫 Restful 資訊：
   - Publish URI：`/api/company`
   - Class Path：`com.company.controller.CompanyController`
   - 選擇已上傳的 JAR 檔案
7. 點擊「儲存」，系統建立 Controller 記錄（狀態：停用）
8. 開發人員點擊「啟用」按鈕
9. 系統動態載入 JAR，註冊 Spring MVC 路由
10. 顯示「啟用成功」訊息，狀態更新為「已啟用」

### 後置條件
- Controller 已啟用並可透過 HTTP 存取
- 外部系統可呼叫：`http://localhost:8080/api/company/{id}`
- JAR 檔案狀態更新為 `INUSED`

### 替代流程
- **4a. 檔案格式錯誤**：系統顯示「僅支援 .jar 格式」，返回步驟 3
- **9a. 類別載入失敗**：系統顯示「類別不存在於 JAR 中」，Controller 保持停用狀態
- **9b. 路由註冊失敗**：系統顯示「路由註冊失敗」，回滾狀態變更

## UC-3：管理 Mock 回應規則

**目標**：測試人員建立 Mock 回應規則，模擬不同情境的 API 回應

### 前置條件
- 對應的 Endpoint 或 Restful 已建立
- 測試人員已登入系統

### 主要流程
1. 測試人員進入「Response 管理」頁面
2. 點擊「新增 Response」按鈕
3. 填寫 Mock 回應資訊：
   - Publish URI：`/ws/company`（從下拉選單選擇）
   - Method：`getCompanyInfo`
   - Condition：`companyId=001`
   - Service Type：`ENDPOINT`
   - Response Content（XML 格式）：
     ```xml
     <company>
       <id>001</id>
       <name>ABC Company</name>
     </company>
     ```
4. 點擊「儲存」，系統建立 Mock Response 記錄（狀態：已啟用）
5. 測試人員可點擊「編輯」修改回應內容
6. 測試人員可點擊「停用」暫時停用該規則

### 後置條件
- Mock 回應規則已建立並啟用
- 符合條件的請求將返回預設回應
- 可在清單中查看該規則

### 替代流程
- **3a. 重複的規則**：系統顯示「此規則已存在」，返回步驟 3
- **3b. 無效的 XML 格式**：系統顯示「XML 格式錯誤」，返回步驟 3
- **3c. 無效的 JSON 格式**：系統顯示「JSON 格式錯誤」，返回步驟 3

## UC-4：切換 API 版本

**目標**：維護人員在不重啟系統的情況下切換 API 版本

### 前置條件
- 舊版與新版的 Endpoint/Restful 都已建立
- 維護人員已登入系統

### 主要流程
1. 維護人員進入「Endpoint 管理」或「Restful 管理」頁面
2. 找到舊版服務，點擊「停用」按鈕
3. 系統卸載舊版服務，顯示「停用成功」訊息
4. 狀態更新為「已停用」
5. 維護人員找到新版服務，點擊「啟用」按鈕
6. 系統載入新版服務，顯示「啟用成功」訊息
7. 狀態更新為「已啟用」
8. 外部系統自動使用新版 API

### 後置條件
- 舊版服務已停用
- 新版服務已啟用
- 系統無需重啟即完成版本切換

### 替代流程
- **6a. 新版載入失敗**：系統顯示錯誤訊息，可重新啟用舊版服務
- **8a. 需要回滾**：維護人員可停用新版，重新啟用舊版

## UC-5：WSDL 轉 Java 輔助開發

**目標**：開發人員使用 WSDL 檔案自動產生 Java 類別，加速開發

### 前置條件
- 開發人員已取得 WSDL 檔案或 WSDL URL
- 開發人員已登入系統

### 主要流程
1. 開發人員進入「Endpoint 管理」頁面
2. 點擊「WSDL 轉 Java」按鈕
3. 在對話框中選擇：
   - 上傳 WSDL 檔案，或
   - 輸入 WSDL URL
4. 點擊「產生」按鈕
5. 系統使用 Apache CXF `wsdl2java` 工具產生 Java 類別
6. 系統將產生的類別打包為 ZIP 檔案
7. 顯示「產生成功」訊息，提供下載連結
8. 開發人員下載 ZIP 檔案
9. 解壓縮後可看到：
   - DTO 類別（如：`Company.java`、`Employee.java`）
   - Service 介面（如：`CompanyWebService.java`）
   - Exception 類別

### 後置條件
- 開發人員取得 Java 類別原始碼
- 可基於產生的程式碼開發 JAR 模組

### 替代流程
- **4a. WSDL URL 無效**：系統顯示「無法存取 WSDL URL」，返回步驟 3
- **5a. WSDL 格式錯誤**：系統顯示「WSDL 格式錯誤」，返回步驟 3
