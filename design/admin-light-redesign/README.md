# 管理介面明亮版重新設計

> 本文是摘要。與 `screens/` 的具體數值不同時，以畫面檔為準；色彩與尺寸的彙整在 `tokens.json`。
> 沒有截圖，以 `screens/*.dc.html` 為準。

- 來源：claude.ai Design 畫布「管理介面現況樣式」中「重新設計：明亮、好操作」分組的四個畫板；取得日期：2026-11-13
- 目標：`nextjs-dynamic-api-manager/`（Next.js 15 + MUI 7），對應既有頁面 `src/app/endpoint`、`src/app/response`、
  `src/dialogs/WsdlGenObjDialog.tsx`、`src/components/Header.tsx`、`src/components/Providers.tsx`、`src/theme/`

## 怎麼讀 screens/ 的檔案

畫面檔是 Design Component 格式，不能直接執行，當成結構與樣式的規格來讀：

- `<x-dc>` 內是畫面；樣式全部寫在 inline `style`，數值可直接取用。`<helmet>` 內是字型與基本樣式。
- `{{name}}` 的值來自檔尾 `<script type="text/x-dc">` 的 `renderVals()`。
- `<sc-for list="{{rows}}" as="r">` 是迴圈，`<sc-if value="{{x}}">` 是條件顯示。
- `renderVals()` 裡的陣列（服務、回應、ZIP 檔案清單）都是**示意資料**，實作時改接真實 API，不可寫死。

## 實作範圍

| 畫面 | 檔案 | 說明 |
|---|---|---|
| 樣式規格 | `screens/tokens.dc.html` | 不是要實作的頁面；是主題色票、字型、元件樣式與刪除確認框的規格 |
| 全站外框（側欄＋頂列） | 三個頁面檔共用的 `<nav>` 與頂列 | 取代現有 `Header.tsx` 的 MENU 下拉 |
| Endpoint 清單 | `screens/endpoint.dc.html` | 改寫 `/endpoint` |
| Mock 回應與編輯側欄 | `screens/response.dc.html` | 改寫 `/response` |
| WSDL 轉換 | `screens/wsdl.dc.html` | 新頁面，取代 `WsdlGenObjDialog` 彈窗 |

不在範圍：畫布「現況」分組的兩個畫板（只是現況記錄，未收進設計包）；`/restful`、`/about`、`/test-api` 沒有設計稿，
只需套用新主題與全站外框並維持原功能，RESTful 清單的版面比照 Endpoint 清單的元件樣式即可，不必新增設計沒畫的功能。

建議拆成三個可獨立驗收的階段：(1) 明亮主題＋全站外框；(2) Endpoint 清單；(3) Mock 回應側欄與 WSDL 轉換頁。

## 視覺規格

- 主題：新增明亮版 MUI theme（`createTheme`，`palette.mode: 'light'`），在 `Providers.tsx` 取代目前的 `techTheme`（深色）。
  `CyberpunkBackground`、`CyberpunkLoader` 等深色風格元件不再用於這些頁面。
- 色彩：白底卡片、`#f5f7fa` 頁面底色、單一藍色主色 `#2563eb`；狀態用綠（啟用）、灰（停用）、琥珀（未上傳、提醒）、紅（刪除）。
  全部色碼與用途見 `tokens.json` 的 `color`。
- 字型：`Inter` + `Noto Sans TC`，等寬字 `JetBrains Mono` 只用在路徑、類別、JAR 檔名、條件、回應內容。
  設計以 Google Fonts 載入；專案生產模式是靜態匯出，載入方式沿用專案既有做法（見未決事項）。
- 字級：頁面標題 24/700、側欄面板標題 16/700、內文 14/400、表頭與徽章 12/600。按鈕文字不轉大寫。
- 圓角：按鈕與輸入框 8、表格內小按鈕 6、卡片 12、徽章全圓。
- 尺寸：按鈕與輸入框高 40、表格列內按鈕高 36、批次列按鈕高 32、側欄項目高 40。
- `tokens.dc.html` 的元件示範與頁面檔數值不同時，以頁面檔為準（例如刪除確認框的按鈕高 36 只適用於確認框）。

## 畫面說明

### 全站外框（三個頁面檔共用）

- 版面：左側固定側欄寬 232、白底、右側 1px `#e5e7eb` 框線；右側內容區上方有高 56 的白底頂列。
  外層是 `flex-wrap`，窄螢幕時側欄換到內容上方，不可出現整頁橫向捲動。
- 側欄內容：品牌區（32×32 藍底圖示、「Dynamic API」、「Mock 伺服器管理」）；分組「服務」：SOAP Endpoint、RESTful API、Mock 回應；
  分組「工具」：WSDL 轉換、系統資訊。目前頁以 `#eff4ff` 底色、`#1d4ed8` 字色、字重 600 標示，並帶 `aria-current="page"`。
- SOAP Endpoint 與 RESTful API 右側的數字是該類服務的總數（示意為 12、8），用真實筆數。
- 頂列：左側麵包屑（例：`服務 / SOAP Endpoint`、`SOAP Endpoint / company / Mock 回應`，可點的層級是連結）；
  右側「後端連線正常 · localhost:8080」加綠色圓點，位址是示意（見未決事項）。
- 對應：系統資訊 → 既有 `/about`；`/test-api` 設計沒有放進側欄（見未決事項）。

### Endpoint 清單（screens/endpoint.dc.html）

- 版面：內容區最大寬 1280，padding `28px 32px 40px`，區塊間距 20。由上到下：頁首（標題＋說明＋右側兩個按鈕）、
  三張統計卡（三等分 grid，間距 16）、表格卡（工具列、批次操作列、表格、分頁列）。表格最小寬 960，放在可橫向捲動的容器內。
- 頁首按鈕：白底「WSDL 轉換」（前往 WSDL 轉換頁）、藍底「新增 Endpoint」（開啟新增表單，沿用 `EndpointForm` 的欄位）。
- 統計卡：全部服務、啟用中（數字 `#15803d`）、尚未上傳 JAR（數字 `#b45309`）。由清單資料計算。
- 工具列：搜尋框（placeholder「搜尋發布名稱、Bean、Class 路徑」，對這三個欄位做篩選）；分段篩選「全部 N／啟用 N／停用 N」，
  單選，選中項白底加陰影並帶 `aria-pressed="true"`。
- 表格欄位：勾選框、服務（發布名稱連結＋等寬小字 `/webservice/<publishUri>`）、實作類別（Bean 名稱＋等寬小字 class 路徑）、
  JAR（等寬檔名；沒有時顯示琥珀色徽章「未上傳」）、Mock 回應（「N 筆 ›」連結，前往該服務的回應頁）、
  狀態（開關＋文字「啟用／停用」）、操作（「編輯」按鈕＋「更多操作」圖示按鈕）。
- 開關：軌道 36×20、圓鈕 16；啟用時軌道 `#16a34a`、文字 `#15803d`，停用時軌道 `#d1d5db`、文字 `#4b5563`。
  切換呼叫既有 `switchWebService`，成功後顯示 toast。
- 批次操作列（`#eff4ff` 底）：「已選取 N 筆」、批次啟用、批次停用、刪除（紅字）、取消選取。
- 分頁列：「顯示 1–5，共 12 筆」、每頁筆數選單（10／50／100）、上一頁／頁碼／下一頁；目前頁碼藍底白字，第一頁時上一頁停用。
- 刪除確認框（樣式在 `screens/tokens.dc.html`）：標題「刪除 2 個 Endpoint？」，內文列出名稱並說明
  「會停止服務，對應的 Mock 回應一併移除，無法復原。」，按鈕「取消」與紅底「刪除 2 個」；數量與名稱依實際選取。
- 狀態：設計沒有畫載入中、無資料、搜尋無結果、載入失敗，需依專案慣例補上（見未決事項）。
- 畫面中同時出現的狀態：
  - 批次操作列：示意資料預先勾選第一列才出現。實際上沒有勾選時不顯示，勾選一筆以上才出現，按「取消選取」或操作完成後消失；
    被勾選的列底色 `#f5f8ff`。
  - 右下角 toast「已啟用 company」＋「復原」：只在操作成功後短暫出現，不是常駐。對應的失敗提示設計沒有畫。
  - 現有程式使用瀏覽器 `alert`／`confirm`（全前端約 19 處）；這些頁面改用 toast 與確認框。
- 示意資料注意：統計（12／7／2）、篩選數量、分頁文字（1–5 共 12 筆）與表格只畫 5 列彼此對不上，
  每頁選單也沒有 5 這個選項；全部以真實資料計算為準。
- 文案（逐字使用）：標題「SOAP Endpoint」；說明「從上傳的 JAR 發布的 Web Service。新建或編輯後預設為停用，確認 Mock 回應後再啟用。」

### Mock 回應與編輯側欄（screens/response.dc.html）

- 版面：側欄＋內容區＋右側編輯面板（寬 400、白底、左框線、陰影 `-8px 0 24px rgba(17,24,39,0.06)`）。
  面板開啟時表格仍看得到；窄螢幕時面板換行到下方或以覆蓋方式呈現。
- 頁首：標題「<發布名稱> 的 Mock 回應」、說明「呼叫時以 方法 + 條件 完全相同且啟用的那一筆回應。」、藍底「新增回應」。
- 資訊卡：類型徽章（SOAP 紫、REST 青，色碼見 tokens）、服務狀態（「● 啟用」綠字或停用）、
  呼叫位址（等寬字、過長以省略號截斷）＋「複製」按鈕。位址是示意，依後端實際格式組出。
- 表格欄位：方法（字重 600）、條件（行內 code；沒有條件時顯示「（無條件）」）、回應內容（單行截斷，最大寬 280）、
  狀態徽章（啟用綠底、停用灰底）。點一列開啟編輯面板；編輯中的列底色 `#f5f8ff` 並有左側 3px 藍線。
- 編輯面板：標題「編輯回應」＋關閉按鈕；欄位「方法名稱」（提示「與 JAR 程式傳入的 method 一致」）、
  「條件」（等寬字，提示「完全相等才會命中，留空代表 JAR 未帶條件」）、「回應內容」（等寬 textarea，最小高 240，右上「格式化」）；
  琥珀色提醒「儲存後此回應會變為停用，需再手動啟用。」；底部左側紅字「刪除」，右側「取消」與藍底「儲存」。
- 回應的啟用／停用：設計在表格只畫了狀態徽章，沒有畫切換控制（見未決事項）。
- 狀態：載入中、無回應資料、儲存失敗、欄位驗證錯誤都沒有畫，需補上。
- 畫面中同時出現的狀態：
  - 編輯面板：示意為開啟且正在編輯第一列。實際上預設關閉，點列或「新增回應」才開啟，儲存、取消或關閉後收起；
    新增時標題與欄位初值設計沒有畫（見未決事項）。
  - 回應內容輸入框的藍色框線與光暈是聚焦狀態，不是常態；未聚焦時框線 `#d1d5db`。

### WSDL 轉換（screens/wsdl.dc.html）

- 版面：頁首（標題「WSDL 轉換」、說明「把 WSDL 轉成 Java 物件並打包成 ZIP 下載，作為撰寫 Endpoint 實作的起點。」）、
  四步驟說明列（1 提供 WSDL／2 下載 ZIP／3 實作並打包 JAR／4 新增 Endpoint，純說明，不是可點的精靈）、
  左右兩張卡「WSDL 來源」與「轉換結果」，下方是失敗狀態示意。
- WSDL 來源卡：
  - 來源類型單選：「WSDL 網址」（說明「服務已上線、後端連得到」）與「上傳檔案」（說明「手邊只有 .wsdl 或 .xml」），
    選中項藍框 `#2563eb`、底色 `#eff4ff`。
  - 選網址：顯示「WSDL 網址」輸入框＋清除按鈕，提示「由後端去讀取，所以要填後端連得到的位址。」
  - 選檔案：顯示拖放區「選擇檔案，或把檔案拖曳到這裡」「接受 .wsdl、.xml，一次一個檔案」。
  - 「Package 名稱（選填）」，placeholder `com.example.endpoint`，提示「留空則依 WSDL 的 targetNamespace 決定。」
  - 卡片底部：「轉換不會新增或變更任何 Endpoint。」與藍底「轉換並下載」。
- API：既有 `POST /dynamic-api/ws/genWsdlObj`，multipart 參數 `wsdlUrl`、`file`、`packageName` 皆選填，成功回 ZIP；
  內容為空時回 204，需當成失敗處理並提示。
- 轉換結果卡：成功時顯示「已產生並開始下載」、檔名、「重新下載」；「ZIP 內容（示意）」檔案清單；
  「實作完成、打包成 JAR 之後：」＋「新增 Endpoint」連結。
- 畫面中同時出現的狀態：
  - 網址輸入與檔案拖放區互斥，依來源類型只顯示一個；示意預設選網址並預填一個示意網址，實際初值為空。
  - 轉換結果卡示意為「完成」。轉換前應是空狀態（設計沒有畫，寫明尚未轉換即可），轉換中要有進行中指示並停用按鈕。
  - 「失敗時的樣子（狀態示意）」區塊只是示意，不是頁面常駐內容：失敗時才在結果位置顯示 alert
    「無法轉換：讀不到這個 WSDL」「請確認網址正確、後端連得到，或改用上傳檔案。輸入的內容會保留，不必重填。」與「再試一次」；
    成功與失敗不會同時出現，失敗後保留使用者輸入。
  - 檔名 `company-wsdl.zip` 與檔案清單是示意：後端固定回傳檔名 `generated_wsdl_object.zip`，且 API 不回傳 ZIP 內的檔案清單。

## 與現況的差異

- 導覽：頂部 `Header` 的 MENU 下拉改為左側固定側欄；新增麵包屑。
- 主題：深色（`techTheme`）改為明亮版。
- Endpoint 清單：新增統計卡、搜尋、狀態篩選、勾選後才出現的批次操作列、Mock 回應筆數連結；操作結果用 toast，刪除用確認框。
- Mock 回應：編輯由彈窗改為右側面板。
- WSDL 轉換：由彈窗改為獨立頁面。新增前端頁面時，依專案 `AGENTS.md` 同步 `backend/build.gradle` 的 `copyNextjsBuild`
  頁面清單與 `SpaController`；這兩個檔案屬後端範圍，依專案規則處理或在報告列為需要後端角色配合。
- 需要但目前 API 沒有或不確定的資料（依實作角色規則列入報告，不自行改後端契約、不用假資料）：
  - 每個 Endpoint 的 Mock 回應筆數：`getEndpoints` 回傳的欄位沒有筆數。
  - 批次啟用／停用：`switchWebService` 一次一筆，沒有批次端點；刪除 `removeWebService` 已可傳多筆。
  - toast 的「復原」：沒有復原 API；啟用／停用可用反向呼叫達成，刪除無法復原。
  - 頂列的後端連線狀態與位址：沒有確認過專用的健康檢查端點。
  - WSDL 轉換結果的 ZIP 檔案清單與依服務命名的檔名。

- 側欄「Mock 回應」沒有指定服務時顯示什麼（現有 `/response` 的行為）沒有說明。

- 載入中、無資料、錯誤、欄位驗證的呈現都沒有設計稿，依專案 UI/UX 原則補上並在報告說明。
