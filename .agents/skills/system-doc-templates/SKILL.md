# System Documentation Templates

本 skill 提供軟體系統文件的標準結構與說明，幫助建立專業的需求規格書（SRS）與設計規格書（SDD）。

## 使用方式

### 建立 SRS（需求規格書）

當使用者需要撰寫需求規格書時：

1. 讀取 `references/srs-template.md` 取得完整的 SRS 模板
2. 根據專案實際內容填入各章節
3. 對於尚未確定的內容，使用 `TODO:` 標記
4. 保持章節編號穩定，便於追蹤

### 建立 SDD（設計規格書）

當使用者需要撰寫設計規格書時：

1. 讀取 `references/sdd-template.md` 取得完整的 SDD 模板
2. 確保設計文件對應到既有的 SRS
3. 根據專案技術棧填入設計細節
4. 記錄重要的設計決策與權衡

## 核心原則

- **避免過早設計**：SRS 保持在需求層級，不引入技術解法
- **保持可追溯性**：需求編號穩定，方便關聯設計與測試
- **文件一致性**：SDD 的模組命名應與 SRS 保持一致
- **記錄決策**：在 SDD 中說明重要決策的理由與取捨

## 模板選擇指引

- **需要描述「系統要做什麼」** → 使用 SRS 模板
- **需要描述「系統要怎麼做」** → 使用 SDD 模板
- **兩者皆需** → 先建立 SRS，再基於 SRS 建立 SDD

## 客製化建議

模板提供標準章節骨架，但可以根據專案特性調整：

- **小型專案**：可以合併或簡化某些章節
- **大型專案**：可以拆分章節或增加子章節
- **特定領域**：可以增加領域特定的章節（如：IoT、金融、醫療）

使用時請依專案實際需求彈性調整，模板是起點而非限制。
